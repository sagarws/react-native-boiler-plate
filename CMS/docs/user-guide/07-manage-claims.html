What you see on this page

Open Manage Claims from the side menu. The claims are read live from TrackVid — the same records the web CMS shows — so you see the full history, not only what this computer has filed.

The page has, from top to bottom:

  1. The toolbar — search box, date range, and action buttons.
  2. Platform tabs — one per marketplace, with a count, and the Export button on the right.
  3. Status tabs — the claim statuses for the chosen marketplace, each with a coloured dot and a count.
  4. The claims table, with a filter box under each column heading.
  5. The page bar — total claims, page number, Rows per page, Previous and Next.
TipThe page opens on the Ajio tab, the Pending status and the last 7 days — the claims that still need filing. Change any of these to see more.

Finding claims: search and dates

Search

Type in the box Search AWB, ticket or order…. The table and all tab counts update to match, and you go back to page 1.

Date range

The date box next to the search limits the claims to those created in that window. It starts at the last 7 days (today included).

  1. Click the date box.
  2. Pick a ready-made range on the left — Today, Yesterday, This Week, Last Week, This Month, Last Month or All Time — or click a start day and then an end day on the calendar. Future days cannot be picked.
  3. The table reloads for the new dates.
NoteIf a claim you expect is missing, check the dates first. The counts on the tabs only count claims inside the chosen date range and search.

Platform tabs

The tabs are, in order: Ajio, Meesho, Snapdeal, Nykaa, Amazon, Myntra, Flipkart, Tata CliQ, Delhivery, Xbees and Other. Each shows the marketplace logo and how many claims it has. Tabs with zero claims look faded, but you can still open them.

  • Switching platform keeps your status tab (for example Pending). If the new platform has no such status, All is shown instead.
  • Switching platform clears the column filters and goes back to page 1.
  • Some buttons only appear on certain platforms: NDR/DDR Bulk Claim on Ajio, Re-Claim on Myntra, Check TAT on Meesho, and Status Change on Ajio, Myntra, Meesho, Snapdeal, Flipkart, Delhivery and Nykaa.

Status tabs

Every platform has these: All, Failed to Proceed, Pending, In Review, Approved, Rejected. Some platforms have extra tabs:

Filtering inside a column

Under every column heading there is a small Search box with a filter icon. These filters only narrow the rows already loaded — they do not change the tab counts.

How to search inside one column

  1. Type in the Search box under the column heading. Rows that do not match are hidden straight away.

How to pick values (like a spreadsheet filter)

  1. Click the filter icon inside the column's search box. A list of the column's values opens, each with how many rows have it.
  2. Use Find a value to shorten the list.
  3. Untick values to hide those rows, or use Select all / Clear. Changes apply as you click — there is no Apply button.
  4. At the bottom, Page X of Y loaded tells you how many pages of claims the list covers. Scroll to the end, or click Load next page, to add the values from the next page.
  5. Click outside the list to close it. A dot on the filter icon shows that the column is filtered.

To remove all column filters, click the Clear column filters icon at the far left of the filter row (shown on tabs where rows can be ticked).

TipOnce a column filter is on, the table shows matches from every page loaded so far, not just the current page. A ticked row that a filter hides is automatically unticked, so you never file something you cannot see.

Pages, Refresh and Export

  • The bottom bar shows N claims · page X of Y. Use Previous and Next to move between pages.
  • Rows per page can be 25, 50, 100 or 200. Changing it goes back to page 1.
  • Refresh (toolbar) reloads the claims and re-checks which platforms this computer may file for.

How to export to Excel

  1. Set the platform, status, dates, search and any column filters so the table shows the claims you want.
  2. Click Export (right of the platform tabs). It is greyed out when the table is empty.
  3. Choose where to save the file.
  4. You will see Exported N claims (and on N sheets if there is more than one platform). Images are not included.
NoteIf the message ends with — N had left this page, refresh to include them, some claims changed while you were exporting. Click Refresh and export again.

Selecting claims

A tick-box column appears at the left of the table only on the Pending and Failed to Proceed tabs (and while Bulk Update or Status Change is switched on). Other tabs hold claims that are already with the marketplace, and filing them again would raise a second ticket.

  • Tick a row's box to select it. The box in the heading ticks every row on the page that can be filed.
  • A greyed-out box means that claim cannot be filed yet. Hover over it to see why.
  • The selection is cleared whenever the list reloads (new tab, search, dates or page).

Create Ticket — filing claims from this computer

When you tick one or more claims, a Create Ticket (N) button appears in the toolbar.

  1. Go to the platform tab and the Pending (or Failed to Proceed) tab.
  2. Tick the claims you want to file.
  3. Click Create Ticket (N).
  4. The app checks that every login needed has a live session. If not, the Update logins first window opens and nothing is started.
  5. Filing runs in the background — one browser per account. Watch it in the Background work panel in the bottom-right corner (row Ticket creation · platform).
  6. When it finishes you see Created N tickets, and if any failed, N failed — reason. The table reloads.

"Update logins first" window

Before Create Ticket, Check TAT, Status Change or a Re-claim run starts, the app checks the marketplace logins it needs. If any is not usable, this window opens. Nothing has been started.

It lists each account with a badge:

BadgeMeaning
Login expiredThe saved session has run out.
Never capturedThis login has never been signed in on this computer.
Marketplace rejected itThe marketplace no longer accepts the saved session.
No login on this machineThe account is not added for your company on this computer. It must be added (and synced) first.
OptionalThis login needs a one-time code (OTP). The action can run without it; its rows are left as they are.
  1. Click Re-capture login (or Re-capture N logins). A sign-in window opens for each account in turn — complete each one.
  2. When all succeed you see Logins updated — press action again. The window closes.
  3. Press the original button again.
NoteIf you see Signed in, but TrackVid still reports no live login for …, the sign-in did not reach TrackVid. Try again from the Login page.

Check TAT (Meesho)

On the Meesho tab, when you tick claims, a Check TAT (N) button appears next to Create Ticket. It asks Meesho whether each claim is still inside its claim window (TAT). Claims that are not are moved to Failed to Proceed.

  1. On Meesho → Pending, tick the claims to check.
  2. Click Check TAT (N). (The login check runs first.)
  3. The Checking claim windows window shows progress, how many are left, and each AWB's answer. You can click Hide — the check keeps running.
  4. At the end a message such as TAT checked on 20 claims: 3 moved to Failed to Proceed, 16 still claimable, 1 could not be checked appears and the table reloads.
ResultMeaning
ME1: TAT expired (Expired)The claim window has closed. Moved to Failed to Proceed.
ME2: Bad sub-order number (Bad sub-order)Meesho did not accept the sub-order number. Moved to Failed to Proceed. Correct the sub-order number.
ClaimableStill inside the window. Nothing changed.
Not checkedCould not find out. Nothing changed — the claim is still in Pending.

Choosing the seller SKU (AJIO)

An AJIO claim cannot be filed without the right SKU when a return has several items. On the Ajio tab, a small refresh icon appears in the Seller SKU cell of a claim that is Pending or Failed to Proceed and has a Username, a POB ID and a Return AWB.

  1. Click the refresh icon in the Seller SKU cell (Read this return's articles from AJIO and choose the SKU).
  2. The Choose the seller SKU window opens and reads the return from AJIO. This signs in to AJIO, so give it a moment.
  3. Each item on the return is listed with its picture (if any), product name and codes (SKU, Sterling, Jio code, EAN, Scan, Qty). If there is only one item, it is chosen for you.
  4. Pick the right item and click Use this SKU.
  5. You see SKU set to … or SKU changed from … to …, and the table reloads.
NoteRead any notes under an item: if AJIO gave no seller SKU, another code (for example EAN) is stored instead — the claim still matches. If two items share a code, check the product before saving. An item with no code at all cannot be chosen. If AJIO returns no items, the window says AJIO returned no articles for this return. Nothing can be chosen.

Bulk Update — change one field on many claims

Use Bulk Update to set one field to one value on many claims at once — for example, to correct a status on forty rows.

  1. Click Bulk Update in the toolbar. The button changes to Cancel update and tick boxes appear on every row, on any status tab.
  2. Tick the claims to change.
  3. Click Edit N selected. The Update N claims window opens.
  4. Choose the Field. The list comes from TrackVid, so it only offers fields that may be changed.
  5. Enter the New value. For fields with fixed choices (such as a status) you pick from a list; otherwise you type. Some fields may be left empty to clear them (Leave empty to clear).
  6. Read the line … will be set to … on all N selected claims. This cannot be undone.
  7. Click the red Update N claims button.
  8. You see Updated X of N claims (claims that already had the value are not counted as changed). Any skipped claims are named. The selection clears and the table reloads.
ImportantBulk Update cannot be undone. Check the number on the red button before you click it.

To stop without changing anything, click Cancel update (or Cancel in the window). If the window shows This TrackVid server does not have bulk update yet…, the server needs updating — tell your admin.

Status Change

Status Change asks the marketplace where each filed ticket now stands (and what was paid) and updates the claim. It is on the Ajio, Myntra, Meesho, Snapdeal, Flipkart, Delhivery and Nykaa tabs. Full steps are on Refill data & status change.

Re-Claim (Myntra)

On the Myntra tab, Re-Claim lets you dispute rejected Myntra SPF claims — reopen each ticket with a written reason and the same proofs, so Myntra checks it again.

ImportantA ticket can be reopened only once. Once a dispute is sent, the same ticket cannot be argued again with a different reason. Write the reason carefully.

Getting the tickets in

When the Re-claim window opens it says Upload a Myntra rejection export to dispute its tickets. You have three choices at the bottom:

  • Upload export — choose Myntra's rejection export (Excel). It needs a ticketId column and an RR Remarks column (the reason sent for each ticket). Issue category is optional. Other columns in the file are shown as they are.
  • Download template — save a blank sheet with the right columns.
  • Add rows by hand — type a few tickets yourself. For each row enter the Ticket id, the Remarks — sent as the dispute and, optionally, the Issue category (blank keeps the ticket's own). Use Add row to add more (the remarks are copied from the row above), the bin icon to remove one, then click Use these N rows. Back returns without using them.

Nothing is sent just by loading the sheet. If a column is missing you will see The sheet has no … column — rows may be thin.

The ticket table

  • The table shows 50 rows per page, with Previous / Next and Rows X–Y of N.
  • Columns: tick box, # (row number in the sheet), Action, Ticket, Remarks — sent as the dispute, Issue category, and, if the export has them, Status, Rejection reason, Created, Rejected, Closed.
  • A row with no ticket id shows No ticket id and cannot be sent.
  • The eye icon beside a ticket id (Read this ticket from Myntra — nothing is sent) opens the ticket so you can read why it was rejected before you argue.
  • The box Why this rejection should be reconsidered — sent only for rows whose Remarks column is empty holds a default reason. Edit it; it is used only for rows with no remarks of their own.

Toolbar

  • Choose an account… — appears if you have more than one Myntra login. Pick the account the disputes are sent from.
  • Filter — ticket, reason… — narrows the rows.
  • Rows from … to to + Select — ticks a range of row numbers (added to what is already ticked).
  • Choose another — load a different file.
  • Re-claim selected (N) — dispute all ticked tickets. Clear unticks all.

When every row on the page is ticked and the sheet has more than one page, a blue note offers Select all N rows (or Select all N matching rows when a filter is on), then Clear the selection.

How to dispute one ticket

  1. Click Re-claim in the row's Action column. The line Disputing … — reading the ticket, reopening it, then reading it back shows while it works.
  2. The ticket window opens with a green (sent) or red (refused) message and what Myntra now says about the ticket.
  3. The row shows a coloured chip with the ticket's new status (or Raised / Refused). Hover for Myntra's message, click to reopen the details. The row's button becomes Re-claim again.

How to dispute many tickets

  1. Pick the Myntra account if asked. If you skip it with several accounts, you will see Choose which Myntra account these disputes are sent from.
  2. Tick the tickets (or use the range / select-all options).
  3. Click Re-claim selected (N). The login check runs first.
  4. A confirmation Re-claim N ticket(s)? tells you how many send their own remarks and quotes the default reason the rest will get. Click Send N dispute(s).
  5. You see Disputing N tickets — it carries on if you close this window, and the result is on the Jobs page.
  6. Tickets are sent one at a time with a short pause between them (Pausing …s before ticket … — spaced out on purpose). The progress card shows Disputing X / Y, the percentage, and how many were raised and refused. The table page follows the ticket being sent.
  7. To stop, click the red Stop after this one. The ticket in progress finishes; the rest are left untouched.
TipA long run carries on if you close the window. The Background work panel shows Re-claim · Myntra with raised/refused counts and, when enlarged, Myntra's reason for each refusal. The finished run is listed on Background Process.

The ticket details window

Title Ticket …. It shows: Ticket, Status, Original status, Validation reason (usually says why it was rejected), Issue category, Return reason, Tracking id, Order, Return, SKU, Style, Compensation and Last modified. Everything else Myntra returned can be expanded. After a dispute, What was sent, and what came back shows Myntra's answer (open automatically if it was refused).

  • Myntra has no such ticket on this account. Check the account, or the ticket id in the sheet. — wrong account chosen or wrong id.
  • Myntra returned no ticket when it was read back. The dispute may still have landed — check the portal before sending it again.
