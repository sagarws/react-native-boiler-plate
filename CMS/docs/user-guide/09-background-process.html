Background process

The Background Process page is the history of every bulk run this computer has done — what went through, what failed and why — and the floating Background work panel shows what is running right now.

What counts as a background process

Many jobs in TrackVid CMS take minutes or hours — bulk claims, re-claims, refills, report syncs. They run in the background, so you can keep using the app (or leave it) while they work. You do not need to stay on the page that started them, and you should not press the start button again "to make sure" — check the panel or this page instead.

There are two places to look:

WhereWhat it shows
Background work panel (bottom-right of the window)Work happening right now, with live progress.
Background Process page (side menu)A record of every finished (and running) bulk run on this computer, newest first.

The "Background work" panel (live progress)

When something is running, a small panel titled Background work floats at the bottom-right corner of the window, on every page. When nothing is running and nothing finished is waiting to be read, the panel is hidden.

The header shows a summary:

  • A spinning icon and 2 running · 45% done — work in progress; the percentage covers all running jobs together.
  • 1 queued — work waiting to start.
  • A green tick and 1 finished — work is done and its result is waiting for you to read.

Panel buttons

ButtonWhat it does
Click the title, or the down-arrowHide or show the list (Hide jobs / Show jobs). The summary stays visible when hidden.
Diagonal-arrows iconShow the tally and failed AWBs — makes the panel bigger and lists every failed AWB with its reason. Press again for Show less.
External-link icon on a jobReopen this job's window — brings back the window that started the job (for jobs that have one, such as a minimised bulk window).
X icon on a jobDismiss — removes a finished job from the panel. Running jobs cannot be dismissed.

What each job line shows

  • Title — what is running and on which marketplace, for example NDR/DDR bulk claim · Ajio, Ticket creation · Myntra, Re-claim · Myntra, SKU lookup · Ajio, or Claim · Flipkart for a single claim.
  • Detail line — the AWB or ticket being worked on, or what the job is doing (for example Starting…, Next in 12s). When finished: a result such as All 20 tickets created or 18 created, 2 failed.
  • Count — 7 of 20, or Running / Queued for a single claim.
  • Progress bar — dark while running, green when finished.
  • Tally — successful (green tick), failed (red cross) and, while running, remaining.

When an AJIO NDR/DDR bulk claim ends, a message also pops up wherever you are, for example NDR/DDR bulk claim finished — Job 1a2b3c4d: 18 successful, 2 failed, 0 skipped. These messages are also kept in the notification centre.

TipA finished job stays in the panel until you dismiss it, so you will not miss the final count. To copy a failed AWB, open the bigger view and select its number.

The Background Process page

Open Background Process from the side menu. The top card says Every bulk run this machine has done, newest first. and has:

ButtonWhat it does
RefreshReads the list again. The list also updates by itself when a run finishes.
Clear history / Clear …Deletes the records shown under the current filter. See How to clear history.
NoteThis page shows runs done on this computer. A run done on a colleague's computer is generally not listed here, because its details were saved on that computer.

Other states:

  • Reading this machine's runs… — loading.
  • Nothing has run here yet — no bulk run has been started on this computer. Start one and it will appear.
  • No job of that kind — there are runs, but none match the filter. Pick All to see the rest.

When Scheduled is selected, a second row of tabs appears so you can pick one scheduled automation: All scheduled, Login update, AJIO report sync, Snapdeal report sync, Flipkart report sync, Refill Data, Status change, Auto claim. For how these are set up, see Scheduled automations.

How to see the details of a run

  1. Open Background Process.
  2. Pick a filter if needed, and click the run's row. Only one row opens at a time; click it again to close.
  3. The details show (after a short Loading…):
    • The full description line.
    • A summary box for runs whose result is not a list (for example backups and scheduled runs).
    • A red box with the error, if the run failed.
    • This job did not run to the end, so the lists below are what it reached — not everything it was given. — if it stopped part-way.
    • Successful (n) — each item that went through, with its reference (for example AWB), the Ticket number when one was raised, and a last column whose heading depends on the run (for example SKU, Myntra status, What was filled, What happened).
    • Failed (n) — each item that did not go through, with the Reason in the marketplace's own words.

Empty lists say Nothing went through on this run. or Nothing failed.

TipRead the Reason column before retrying. Many failures repeat for the same cause (for example an expired login — see Login), and fixing the cause first saves a wasted run.

How to download a report

For bulk claims, re-claims, account mapping and refills you can save the result as a spreadsheet. (Backups, report syncs and scheduled runs have no report — their rows went into the backup itself.)

  1. Open the run's row.
  2. Press Download report at the top of the details.
  3. Choose where to save the file and confirm.
  4. A message confirms: Report saved — 18 successful, 2 failed.

How to clear history

The clear button removes only what the current filter shows.

  1. Pick the filter you want to clear (or All for everything).
  2. Press Clear history (with All) or Clear … (for example Clear refill data).
  3. Read the confirmation (Clear every job history? or Clear the … history?) and press Clear.
  4. You see Cleared n records (or There was nothing to clear).
ImportantClearing cannot be undone. For some runs (such as Myntra re-claims) this page is the only record of what was done. Download the report first if you may need it. Runs recorded by TrackVid for other machines are not affected and may still appear after clearing.

Closing the app while something is running

If you close TrackVid CMS while a background process is running, a box Close TrackVid CMS? appears saying the job is still running and Closing now can stop it part-way through.

ButtonWhat it does
Keep runningCancels closing. The job continues. (Recommended.)
View Background ProcessCancels closing and opens the Background Process page.
Quit anywayCloses the app. The step in progress finishes and nothing new is started.
NoteIf you quit during a claim run, a claim being filed at that moment may exist on the marketplace without TrackVid recording it, and the next run could file it again. Keep the app open until the run finishes whenever you can.

Stopping and retrying

The Background Process page and the Background work panel are for watching and reviewing — they do not have stop or retry buttons.

  • To stop a run, reopen the window that started it (the external-link icon in the Background work panel, where available) and stop it there.
  • To retry failed items, fix the cause shown in the Reason column, then start the work again from the page where it was started — for example Bulk claim, SPF bulk claim (AJIO), Manage claims or Refill data & status change. The downloaded report is a handy list of exactly which items failed.
  • Scheduled runs retry on their next scheduled time. See Scheduled automations.
