Refill data & status change

Refill Data fills in the missing details a claim needs before it can be filed; Status Change asks the marketplace where an already-filed ticket now stands.

Refill Data and Status Change — the difference

Refill DataStatus Change
Question it asks"What are the missing details for this return?""Where does this filed ticket stand now, and what was paid?"
Which claimsPending claims (not yet filed)Claims that are already filed (have a ticket)
What it changesFills empty fields only — values already there are keptUpdates the claim status (and amount paid)
How you run itAutomatically, as a scheduled taskFrom the Status Change button on Manage Claims, or automatically as a scheduled task
TipIf a claim on the Pending tab has a greyed-out tick box with a message like POB ID missing, Sub-order number missing or No … account on this claim, that is exactly what Refill Data is for. After the next Refill Data run, the claim can usually be filed.

How to run Status Change from Manage Claims

The Status Change button is in the toolbar of Manage Claims on the Ajio, Myntra, Meesho, Snapdeal, Flipkart, Delhivery and Nykaa tabs. It is not offered on Tata CliQ, Xbees, Amazon or Other.

  1. Open Manage Claims and click the platform tab.
  2. Choose a status tab and date range that show the filed claims you want to check (for example In Review).
  3. Click Status Change. The button turns dark and now reads Cancel status change. Tick boxes appear on the rows.
  4. Tick the claims to check. Only claims that have a Return AWB and are not Pending can be ticked (a Pending claim has no ticket to ask about). The box in the heading ticks every eligible row on the page.
  5. Click Run Status Change (N). It is greyed out until you tick at least one claim.
  6. The app checks every login on that marketplace first (it asks each account in turn which one holds the ticket). If any login needs attention, the Update logins first window opens and nothing is started — re-capture the logins and press the button again.
  7. The Refilling claim data window opens and shows progress (see below).
  8. At the end you see a message such as Status updated on 12 claims, 30 already had what the marketplace says, 2 not found on any account, 1 failed. The table reloads.

To leave without running anything, click Cancel status change or Cancel.

Note"Already had what the marketplace says" is a good result — the ticket simply has not moved. A message shown in red means nothing was updated and some claims were not found or failed.

The progress window and its results

The Refilling claim data window shows N of M to go — Claim status, a progress bar, and the AWB being asked about (Asking about …). You can click Hide at any time — the run keeps going. When it ends the button reads Close and the line says Every claim answered. or N of M came back with no answer — see below.

Box / row labelMeaningWhat to do
FilledSomething was written to the claim (for example a new status).Nothing.
UnchangedThe marketplace was asked and the claim already matched.Nothing.
Not foundNo login on this marketplace has this AWB, so nothing could be asked.Check the AWB and the Username on the claim. The account may be missing on this computer.
FailedThe marketplace call or the save broke. The message beside the AWB says why.Read the message. Often a login issue — re-capture it on the Login page and try again.

Below the four boxes, the latest AWBs are listed with their result and message (hover to read a long message).

Refill Data — what it fills

Refill Data asks each marketplace for the details a claim is missing. It only fills empty fields; anything already on the claim is kept. What it can fill depends on the marketplace:

NoteIn normal use, Refill Data runs as a scheduled task — there is no Refill Data button on Manage Claims for operators. To fix a single AJIO SKU yourself, use the refresh icon in the Seller SKU cell (see Choosing the seller SKU).

The scheduled Refill Data task

In Settings the task is called Refill Data, with the description: Asks each marketplace for the blanks on claims that are waiting to be filed — the account, the POB ID, the sub-order number, the forward AWB. The claim status is its own task, below. By default it runs every day at 23:00. To change the time or switch it off, see Scheduled automations.

What it does each time it runs:

  1. Reads every Pending claim from TrackVid, for all marketplaces.
  2. Skips marketplaces with nothing to fill (Nykaa), and claims with no Return AWB.
  3. Skips claims it has already asked about 3 times without success — the AWB is probably wrong, and asking again would not help. These are counted separately so you know why fewer claims were checked.
  4. Skips a marketplace where no login has a live session (it shows as skipped rather than opening sign-in windows in the night). AJIO is the exception: its answers come from this computer's AJIO report backup, which needs no sign-in.
  5. Goes marketplace by marketplace, asking about each claim and filling the empty fields.
TipFor AJIO, Refill Data can only fill what the local backup holds. Keep the AJIO report sync task switched on (it runs at 10:00 by default) so the backup is up to date.

While it runs, the Scheduled automations window (opened with the button beside the Automations switch at the top of the app — tooltip What is running, queued and scheduled) lists every marketplace it will reach — waiting, running, done or skipped — with the number checked and changed. The finished run appears on Background Process.

The scheduled Status change task

In Settings the task is called Status change: Asks where each already-filed ticket now stands, and what was paid. Skips Pending, Failed to Proceed, Approved and Rejected — those have nothing filed yet, or cannot move. By default it runs every day at 13:00.

  • It asks about claims that have a ticket number and a Return AWB, on every marketplace that reports a status (not Tata CliQ or Xbees).
  • Claims it has checked within the last few days are left alone and shown as up to date, so each run only asks about claims that are due.
  • There is no 3-try limit here — "still In Review" is a real answer, and the next day's answer may be different.

How the tasks fit together

When several tasks are due at once they run in this order, because each one prepares the next:

  1. Login update — re-captures expired logins, since everything below signs in.
  2. AJIO report sync (and Snapdeal / Flipkart report sync) — refreshes the local backups Refill Data reads.
  3. Refill Data — fills the blanks that stop claims from being filed.
  4. Auto claim — files the Pending claims that are now ready.
  5. Status change — last, so tickets filed in this pass are included.

Only one automation uses the browser at a time; if two are due together, one waits for the other.

ImportantSwitching off the Automations switch at the top of the app stops these tasks. A running Refill Data or Status change finishes the marketplace it is on and does not start the next one. Nothing scheduled runs until you switch Automations back on.

Common problems

ProblemFix
The Status Change button is not shownThe platform does not report a claim status (Tata CliQ, Xbees, Amazon, Other).
I cannot tick a claim after pressing Status ChangeIt is Pending (no ticket yet) or has no Return AWB.
"Update logins first" opens every timeRe-capture the listed logins. Accounts marked Optional need an OTP and can be left; the run continues without them.
Many claims show Not foundThe AWB is not on any login on this computer. Check that all the company's marketplace logins are added and signed in.
A Pending claim still has a blank POB ID / sub-order / account after several nightsRefill Data stops asking after 3 tries. Check the AWB is correct, or import the master data that carries the missing value.
Refill Data did nothing for a marketplaceNo live login for it at run time — re-capture on the Login page. Also check Automations is switched on.
