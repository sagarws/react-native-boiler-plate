Login (marketplace sign-ins)

What a "login" (session) is

Every automation in TrackVid CMS — creating claims, downloading reports, refilling data — works by talking to the marketplace's seller portal (AJIO, Myntra, Flipkart, Snapdeal and so on). To do that it needs to be signed in to that portal. When you sign in once, the app saves that sign-in (called a session or login) and re-uses it until it runs out.

  • Each account (seller username) on each marketplace has its own saved login.
  • A saved login lasts only a limited time. After that, the marketplace asks for a fresh sign-in.
  • Before using a saved login, the automations check it with the marketplace, and sign in again if it has stopped working (when automatic sign-in is allowed).
  • The accounts and passwords themselves are added in TrackVid (the web panel), not in this app. This page only manages the sign-ins.

The short line at the top of the page says the same: Sign in to a marketplace once. Automations check each saved login with the marketplace before using it, and sign in again if it has stopped working.

The red warning and the count in the side menu

When one or more logins need attention, a number appears on the Login item in the side menu, on every screen. This is the number of accounts whose login needs updating.

On the Login page (and on the Create claim page), a red strip appears above the page:

3 logins need updating — automations that sign in will fail until they are

It lists each marketplace as a small chip (for example Myntra · 2; hover over a chip to see the usernames) and has an Update now button. The strip cannot be closed — it goes away by itself once the logins are updated. See How to update all logins at once.

The page at a glance

At the top of the page is a card with:

ItemWhat it does
RefreshReads the latest login status again. Greyed out while something else on the page is running.
Clear all loginsRemoves every saved login for your company, on every marketplace. Only shown when at least one login is saved. See Removing saved logins.
X of Y accounts have a working saved loginA quick summary with a green tick. X is the number of accounts whose login is Saved.

Below the card is the table of marketplaces. Only marketplaces your company actually has accounts for are listed.

  • A marketplace with one account shows that account on the same row.
  • A marketplace with several accounts shows one summary row (for example 3 accounts and a badge such as 2 need attention or 3 saved). Click the row (or the arrow at its left) to open or close the list of accounts underneath. If any account needs attention, the list opens by itself.

Other states you may see:

  • Reading this company's marketplaces… — the page is loading.
  • No marketplaces yet — your company has no marketplace accounts set up. Ask your administrator to add them in TrackVid.
  • A red box with an error message — the page could not read the login status (often because the app is not signed in to TrackVid or there is no internet). Fix the cause and press Refresh.
  • An amber box saying The server did not report … — the TrackVid server is an older version and does not know some marketplaces yet. Tell your administrator.

Status colours: what they mean

StatusMeaningWhat to do
SavedA login is saved and has not reached its expiry time. Automations will use it.Nothing.
ExpiringThe saved login will run out within about 2 hours. It still works, but a long batch started now could stop halfway.Re-capture before starting a big run.
ExpiredThe saved login's time is over. Automations that need this account will fail or be skipped.Re-capture.
RejectedThe login has not timed out, but the marketplace has stopped accepting it (for example you signed out on the portal, or signed in from somewhere else).Re-capture.
No loginThis account has never been signed in from TrackVid.Press Capture.

Button colour also helps: the Capture / Re-capture button is filled (dark) on rows that need work, and plain on rows that are fine — so a quick look down the Actions column shows what needs doing.

TipSaved means a login is stored and its time has not run out. It is not a guarantee that the marketplace still accepts it — the automations always check before using it.

How to capture or re-capture a login

The button reads Capture for an account that has never been signed in, and Re-capture for one that has.

  1. Open Login from the side menu.
  2. Find the marketplace. If it has several accounts, click its row to show them.
  3. Press Capture or Re-capture on the account's row.
  4. A sign-in window opens showing the marketplace's own login page. The row shows a spinner and a message:
    • Signing in — finish any code, then close the window — when Sign-in is Auto. The app types the username and password itself. If the marketplace asks for an OTP or a captcha, type it in the window.
    • Sign in, then close the window — when Sign-in is Manual. Type the username, password and any OTP yourself.
  5. Wait until the marketplace's seller dashboard has loaded. The app watches the window and usually closes it by itself once you are signed in. If it stays open, close it yourself after the dashboard appears.
  6. A green message confirms it, for example Myntra login saved for name@company.com (12 cookies). The status changes to Saved.
NoteOnly one action at a time. While a capture is running, the other buttons on the page (and Refresh) are greyed out. Only one sign-in window per marketplace can be open at a time.

To stop a capture, press Cancel next to the spinner, or simply close the sign-in window. Nothing is saved and the old login (if any) stays as it was.

ImportantDo not close the window before the seller dashboard has loaded. If you do, you will see No … login found — the window was closed before sign-in completed. Just press Re-capture again.

How to update all logins at once

The red strip at the top of the Login page has an Update now button that re-captures every login that needs it, one after another.

  1. Press Update now on the red strip.
  2. Sign-in windows open one at a time. The chip of the marketplace currently being signed in turns green.
  3. Enter any OTP or captcha the marketplace asks for, in each window.
  4. When all are done you see All logins updated. Any that failed show a red message naming the marketplace and the reason.
NoteUpdate now skips accounts that are Unverified — signing in with a password the marketplace has refused only repeats the refusal (and some marketplaces, such as Delhivery, lock the account after several failed tries). You will see a message like Delhivery: unverified — use Verify on the Login page first. Fix those with Verify.

Sign-in: Auto or Manual

Shown asMeaning
AutoRe-capture signs in by itself — the app fills the username and password from TrackVid. You only need to step in if the marketplace asks for an OTP or a captcha.
Manual (amber)The app cannot sign in by itself; you must type the sign-in in the window. Hover over it to see why.

The hover text for Manual gives one of these reasons:

  • Automatic sign-in is off for this platform in Trackvid-Monitor. Turn it on there and the nightly Login update will do this account without anybody present. — Your administrator controls this setting (called "auto login on active session") in Trackvid-Monitor. Ask them to turn it on if you want hands-free sign-in.
  • Automatic sign-in is turned off on this installation. — This copy of the app has automatic sign-in disabled.
  • This build has no scripted sign-in for this platform … — The marketplace needs a code that only the automation server can read. Re-capture it here by hand, or renew it from Monitor.

For how the nightly Login update uses this, see Scheduled automations.

The OTP switch (Snapdeal and Flipkart)

On Snapdeal and Flipkart, some seller accounts ask for a one-time code (OTP) at sign-in and some do not — it depends on the account's own settings. The app cannot tell which without trying, so you tell it with the OTP switch on each account's row.

  1. Check whether this account asks for an OTP when you sign in on the marketplace.
  2. Turn the OTP switch on if it does, off if it does not.
  3. A message confirms: … will be signed in with a one-time code or … will be signed in without waiting for a code. If saving fails, the switch flips back and a red message explains why.
TipSet this correctly. With OTP on for an account that never asks for one, every sign-in waits for a code that never comes. With OTP off for an account that does ask, the sign-in fails. Tata CliQ has no switch because every Tata CliQ sign-in asks for a code.

Unverified accounts: how to fix a wrong password

Unverified in the Verified column means the marketplace refused this account's username or password. While an account is unverified, every automation skips it, and re-capturing will keep failing. The fix is to enter the correct details.

  1. Press Verify next to Unverified.
  2. A window Verify name@company.com opens. It explains: The marketplace refused this login, so every automation is skipping it. Correct it below and TrackVid will sign in with it — it goes back into the automations only if that sign-in works.
  3. Check or correct the Username, and type the current Password.
  4. Press Save and verify. The button changes to Signing in… while the app tries to sign in with the new details.
  5. If it works, the window closes and you see … verified — it is back in the automations. The column changes to Verified.
  6. If the marketplace still refuses, its own message (for example "Invalid Username or Password") appears in red inside the window. Correct the details and try again, or press Cancel.
NoteSaving here also updates the password stored in TrackVid. If someone changed the password on the marketplace, update it here (or in TrackVid) straight away — otherwise the account stays skipped.

The Update button (saved here, not on the server)

Sometimes a sign-in succeeds but the app cannot reach the TrackVid server to store it (for example the internet dropped). In that case you see: Signed in to …, but the server is unreachable. The login is saved on this machine — use Update to send it when you are back online.

  1. When the connection is back, open Login.
  2. Press the dark Update button on that account's row (hover shows Captured … — not yet saved to the server).
  3. On success: … login saved to the server, and the Update button disappears.

If the server is still unreachable you see Still cannot reach the server. The … login is still saved here. — try again later. If the server rejects it, re-capture the login instead.

POBs (AJIO) and Slaves (Tata CliQ)

Two marketplaces need an extra list for each account before claims can be filed:

MarketplaceButtonWhy it is needed
AJIOPOBs (n)Places of business. AJIO claims, account mapping and the SKU lookup all need them.
Tata CliQSlaves (n)A Tata CliQ return is only visible to the slave that owns it, so claims need this list to search.

The number on the button is how many are stored. If none are stored, the button reads POBs — not synced or Slaves — not synced in amber.

  1. Make sure the account's status is Saved (re-capture first if needed).
  2. Press the POBs / Slaves button. It shows Syncing….
  3. A message confirms the count, for example 4 POBs for name@company.com · 1 new.

Press it again any time to re-sync (for example after a new place of business is added on AJIO). Hover over the button to see when it was last synced.

Removing saved logins

Remove one login

  1. Press the bin icon at the end of the account's row (only shown when a login is saved).
  2. The box Remove this login? names the marketplace and account. It explains that the account and password are kept — only the saved login goes.
  3. Press Remove login to confirm, or cancel.

Remove all logins

  1. Press Clear all logins at the top of the page.
  2. The box Remove every saved login? tells you how many will be removed.
  3. Press Remove all logins to confirm.
ImportantRemoving logins cannot be undone. Every removed account must be signed in again, and accounts that need an OTP will need someone present to read the code. Only do this when asked to (for example when handing over the machine).

"Update logins first" — when a claim action needs a sign-in

When you press a marketplace action such as Create Ticket or Check TAT, the app first checks that the accounts it needs have a working login. If some do not, nothing is started and a window Update logins first opens:

Nothing was started. Kindly re-capture these logins, then press Create Ticket again.

It lists each account with its marketplace and one of these badges:

BadgeMeaning
Login expiredThe saved login has run out.
Marketplace rejected itThe login has not run out, but the marketplace no longer accepts it.
Never capturedThis account has never been signed in.
No login on this machineThe account is not set up on this machine. It must be added to the company in TrackVid (and synced) first — it cannot be re-captured here.
OptionalThis account signs in with a one-time code. You can leave it; the action will run without that account and its rows stay as they are. Capture it later from the Login page when you have the code.
  1. Press Re-capture login (or Re-capture N logins). Optional accounts are not included.
  2. Sign-in windows open one at a time; the account being signed in shows Signing in…. Complete any OTP or captcha.
  3. If all succeed, you see Logins updated — press Create Ticket again and the window closes. Press your action button again.
  4. If a sign-in fails, a red message names the account and the reason. If the app still sees no working login after signing in, you see Signed in, but TrackVid still reports no live login for … Nothing was started. — go to the Login page and re-capture that account there.

Press Cancel to close the window without doing anything.

Notes for particular marketplaces

MarketplaceWhat to know
Snapdeal, FlipkartHave the OTP switch. Set it per account.
Tata CliQEvery sign-in asks for a one-time code, so someone must be present. Needs Slaves synced.
AJIONeeds POBs synced before claims, account mapping and SKU lookup will work.
MyntraWhen signing in by hand, the sign-in opens in the installed Google Chrome browser instead of the app's own window (Myntra refuses the app's window). Sign in there; closing Chrome cancels. Only one Myntra sign-in can be open at a time.
Delhivery, XbeesThese sign in with tokens, not cookies, so they cannot be captured by typing in a window. They need automatic sign-in turned on (in Trackvid-Monitor), or the login must be renewed from Monitor. Delhivery locks an account after repeated wrong passwords — fix Unverified with Verify before retrying.

What to do when a login expires

  1. Look for the number on the Login menu item, or the red strip at the top of the Login or Create claim page.
  2. Open Login. Rows with Expired, Rejected, Expiring or No login need work; their Capture button is dark.
  3. If any account is Unverified, fix it first with Verify.
  4. Press Update now on the red strip to do them all, or Re-capture on each row.
  5. Complete any OTP or captcha in the sign-in windows.
  6. Check the status shows Saved, then restart the work that failed (for example press Create Ticket again).
TipRe-capture logins at the start of the day, before starting bulk runs. An Expiring login can run out halfway through a long batch.
