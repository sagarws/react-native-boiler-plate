Bulk claim

Turn a whole Increff QC report into claims in one go — upload the sheet, let the app match each row to your recorded return videos and check it, then create all the ready claims with one click.

What Bulk Claim does

Bulk Claim reads the Increff QC report (CSV or Excel) and, for every row:

  1. finds the return video recorded in TrackVid (VMS) for the row's Return Gate Entry AWB,
  2. works out the marketplace from the row's Sales Channel and the claim type from its QC Reason,
  3. checks that everything the marketplace needs is available, and
  4. lets you create a claim for every row that passed — in one click.

Photos are taken from the screenshots of the recorded return video, so you do not attach images by hand. The new claims appear in Manage Claims, the same as claims saved with Save on the Create claim page.

This is not the SPF bulk claim

NoteThere are two different bulk tools. Bulk Claim (this page) works on the Increff QC report for several marketplaces and is opened from the Create claim page. The NDR/DDR Bulk Claim is for AJIO SPF claims (returns not delivered or delivery disputes), uses a different spreadsheet, and is opened from Manage Claims — see SPF bulk claim (AJIO).

Where to find it

  1. Click Create claim in the side menu.
  2. In the top bar, click Bulk Claim. The Bulk Claim window opens.
TipIf you do not see the Bulk Claim button, your company does not have it switched on. It appears only when your administrator has enabled automatic claim creation through the Increff report and enabled at least one marketplace for it. Ask your admin or TrackVid support.

The file you upload

Upload the Increff QC report as exported. Accepted formats: .CSV, .XLSX, .XLS. Only the first sheet is read, and the first row must hold the column names.

The file must contain all of these columns (capital letters and extra spaces do not matter; column order does not matter):

Column nameAlso accepted asWhat it is used for
Return Order Type—Nykaa: sets the Return Type (Return to origin → RTO, customer return → DTO, anything else → REPL).
Sales Channel—Which marketplace the row belongs to (for example MYNTRA_USPA, TATACLIQ, FLIPKARTV3).
Return Gate Entry AWB—The return AWB — matched against your recorded return videos.
QC Reason—Translated into the marketplace's claim type.
Client SKU ID / EANClient SKU ID/EAN, Client SKU ID, EANThe SKU (Nykaa uses it as the SKU ID).
Forward AWB NumberForward AWB NoSaved as the claim's forward AWB.
Forward Unit Base PriceUnit Base PriceRead from the sheet.
  • Up to 1,000 rows are read from one file. Split bigger reports into several files.
  • Completely empty rows are skipped.
  • Long AWB numbers that Excel shows as 2.84E+13 are read back correctly — you do not need to reformat them.
  • Rows whose Sales Channel is not one of the marketplaces enabled for your company are left out silently and are not counted.
ImportantIf a column is missing, the upload is refused with Missing required column(s): … naming the missing columns. Add the column (it may be empty for rows that do not need it) and upload again.

How to create claims from a report (step by step)

  1. Open the Bulk Claim window (see Where to find it).
  2. Click the box Click to browse or drag-and-drop and pick your file — or drag the file from a folder and drop it on the box.
  3. The file name and size appear. The app works through two stages on its own: Checking VMS… (matching each AWB to a recorded video) and then Verifying rows… (checking each row can become a claim). Wait until they finish.
  4. The results appear: the counters Total rows, Success and Failed, and the tables below them.
  5. Look at the Failed table and its Reason column to see which rows cannot be created and why (see Why a row failed).
  6. Click Create Claims (N) at the bottom right. N is the number of rows that passed every check.
  7. When it finishes you see a message such as Created 42 of 45 claim(s). and the window switches to the Success list.
  8. Click Download PDF to keep a record, then Close.
TipTo try a different file, close the window and open it again. Closing the window clears everything shown in it — claims already created stay created.

What the app checks for each row

A row can only be created when all of these are true:

CheckWhy it matters
A return video was recorded in TrackVid for the Return Gate Entry AWBEvery claim needs the return video. Upper/lower case in the AWB does not matter.
The Sales Channel matches one of your company's marketplacesThe claim must be filed under a known marketplace.
The QC Reason has a mapping to a claim type for that marketplaceThe mapping is maintained by TrackVid. An unknown QC reason cannot be turned into a claim.
That claim type is set up for your company on that marketplaceThe marketplace would refuse a claim type you have not configured.
The recorded video has enough screenshots for the photos the marketplace needsThe first screenshot becomes the main photo (for example the shipping label), the rest fill the other photo boxes. AJIO and Nykaa need at least 4 screenshots (1 + 3 side images); Myntra, Flipkart, Tata CliQ and Amazon need at least 2.
Marketplace extras are availableNykaa needs a vendor code saved on your company's Nykaa login and a SKU in the sheet. Delhivery and Xbees need details the sheet cannot supply (see Why a row failed).

Creating the claims

  • The Create Claims (N) button only counts rows with a green tick. Rows that failed a check are never sent.
  • The button is greyed out while checking or verifying, while creating (it shows a spinning circle), or when no row passed.
  • Each claim is created with the marketplace's photo boxes filled from the video screenshots, the forward AWB from the sheet, and the feed of the recorded video.
  • Creating does not file the claims on the marketplace. They wait in Manage Claims until filed.
ImportantDo not upload the same report again after creating claims from it — it would create the same claims a second time. Fix only the failed rows and upload a file with just those rows.

Downloading the results PDF

After Create Claims has run, the button changes to Download PDF.

  1. Click Download PDF. While it is being made the button reads Generating….
  2. The file is saved as [your file name]-results-[date].pdf.
  3. It has two parts, each starting on a new page: Bulk Claim — Success (N) and Bulk Claim — Failed (N), with Row #, Return AWB, Sales Channel, QC Reason, VMS Matches and the Status or Reason. Long text is shortened with "…".
