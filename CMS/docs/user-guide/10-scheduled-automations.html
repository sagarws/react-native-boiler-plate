Scheduled automations

The app can do routine work by itself at set times — refresh marketplace logins, download reports, fill missing claim details, file ready claims and check claim status — so nobody has to press a button for it.

How scheduled automations work

Each scheduled task has an on/off switch and a schedule. When its time comes, the app starts it on its own — no one needs to be at the computer.

  • The app must be open. Nothing runs while the app is closed. If a time was missed while the app was closed (or the computer was asleep), the missed run happens once the next time the app is open.
  • All times are IST (Indian Standard Time), whatever clock the computer uses.
  • Tasks run one at a time, never two together. If two tasks are due at the same moment, they run in a fixed order (see the next section). The others wait in a queue.
  • A task also waits if the browser is busy — for example while a bulk claim you started is still running. It starts as soon as the browser is free.
  • A task that has never run on this computer runs straight away the first time the schedule checks, whatever its time says.
  • After the app has been closed, the Login update runs first, before anything else that was missed, so the other tasks have working logins.
  • Every run is recorded. You can see it in the task's History, in the Run history tab, and on the Background Process page.
TipThe schedule is switched on, with the default times, on a new installation. You do not need to set anything up to get started — just keep the app open.

The tasks, in run order

When more than one task is due, they always run in this order. The order matters: logins come first because every other task signs in to the marketplace, and the reports and blank details come before claim filing so that claims are ready to file.

The schedule only decides when a task starts. Each task does exactly the same work as the matching button elsewhere in the app (for example, Refill Data on the Manage Claims page).

The Automations switch (sidebar)

At the bottom of the left sidebar, above the version number, is the Automations switch. It is the on/off switch for all background work, on every screen.

Text under the switchMeaning
IdleAutomations are on, and nothing is running at this moment.
Running 1 / Running 1 · 2 queuedA task is running (with a spinning icon). "queued" is the number of tasks waiting their turn.
Stopping…You switched it off while a task was running. The task finishes the step it is on (for example, the claim in hand) and then stops.
OffNothing runs in the background.

How to stop all automations

  1. Find the Automations switch at the bottom of the sidebar.
  2. Turn it off. A message appears: "Automations off — nothing runs in the background until you switch it back on." If something was running, it says "Automations off — what is running stops after the step it is on."

Switching off also stops the master-import schedule and other background processes. It stays off even after you close and reopen the app. Your task switches and times are kept.

How to start them again

  1. Turn the Automations switch on.
  2. The message "Automations on — catching up on anything that was missed." appears.
  3. The app now runs every task that is switched on, once, straight away, starting with the Login update and then in the usual order, one at a time. Tasks you have switched off are not run.
NoteBecause turning the switch on runs every enabled task (including Auto claim), only switch it on when you are happy for that work to happen now.

The eye button beside the switch (tooltip "What is running, queued and scheduled") opens the Scheduled automations dialog.

How to set or change a task's time

  1. Go to Settings.
  2. On the task's row, click the schedule button (it shows the current setting, such as At 10:00). The Set cron — task name window opens. It reminds you: "Times are IST. The app has to be open for a run to happen, and a window it missed is picked up the next time it opens."
  3. Under How should this run? choose one:
    • Rotate — "Every so often, round the clock".
    • Fixed time — "At the times you choose".
  4. For Rotate: in Run every, enter hours and minutes. For example 00:15 means every 15 minutes, 02:00 means every 2 hours. The gap is counted from the end of the last run.
  5. For Fixed time: in Run at, enter a time (24-hour, IST). To run more than once a day, click Add another time and enter the next time. Use the bin icon to remove a time (the last one cannot be removed).
  6. Click Save cron. To leave without changing anything, click Cancel.
  7. Check that the row's switch is On. If it is Off, turn it on.

If something is wrong, an amber message appears and Save cron stays greyed out:

MessageWhat to do
Enter how often this should runEnter a time greater than 00:00 in Run every.
Five minutes is the shortest interval — anything less never finishes before it is due againUse 00:05 or more.
A day is the longest interval — use a fixed time insteadChoose Fixed time instead.
Add at least one timeEnter a time under Run at.
Enter each time as HH:mm, for example 02:00Fill in every time box completely.

TipDo not put two tasks on exactly the same minute. They cannot run together anyway — the second just waits for the first.

How to turn a task on or off

  1. Go to Settings.
  2. Click the switch on the task's row. It shows On or Off.
  3. If you turn on a task that has no schedule yet, the Set cron window opens first so you can choose one.

A task that is Off never runs on its schedule, and is not run when the Automations switch is turned on. Its history is kept.

NoteThe task switch is different from the Automations switch in the sidebar. The task switch decides which tasks this computer does. The Automations switch is a "stop everything for now" switch that remembers which tasks were on.

How to run a task now

  1. Go to Settings.
  2. Click Run now on the task's row. A message "task name started" appears.
  3. Watch the row: the Running badge and the details under the row update as the task works.
  4. When it ends, a message shows the result, for example "Auto claim — summary", or an error in red.

Run now does exactly what the schedule would do. It runs only that one task (not the tasks after it). It still waits its turn if another task is running.

If Run now is refused with…Why
Automations are switched off — switch them on to run this.The sidebar Automations switch is off. Turn it on (remember this also starts all enabled tasks).
(job) is using the browser — try again when it endsAnother job, such as a bulk claim, has the browser. Wait for it to finish.
(task) is already runningThat task is already going or already waiting. Do not press again.

The Run now button is greyed out while the task is running, or while another Run now you pressed is still going.

When a task fails — retries and Skip this run

When a task fails, the app does not give up:

  • The tasks after it in the order still run.
  • The failed task is tried again automatically at the app's next routine check (at least every 30 minutes), until it succeeds. There is no limit on retries.
  • After more than one failure in a row, the row shows the red "Failed N times in a row" warning.

Some failures cannot fix themselves — for example a login that needs a person. Fix the cause (often on the Login page), or stop the retries with Skip this run.

How to skip a failed run

  1. Go to Settings. The Skip this run button appears only on a row whose last run failed, and is greyed out while the task is running.
  2. Click Skip this run. A confirmation window "Skip this run?" opens.
  3. Click Skip this run again to confirm.
  4. A message says "task name skipped — the tasks after it can run now".

Skipping records the failed run as passed over. The work that run would have done does not happen, the app stops retrying it, and the task runs normally again at its next scheduled time.

How to reset the schedule

  1. Go to Settings.
  2. Click Reset at the top right of the schedule card. The window "Reset the schedule?" opens.
  3. Read the warning, then click Reset to confirm, or cancel.
  4. The message "Schedule reset — every automation back on, at its default time" appears.

Reset turns every task back on, at the default times shown in the task table. The history of past runs is kept.

ImportantReset also switches Auto claim back on, which files real claims. If you had turned Auto claim off on purpose, turn it off again after a reset.

What each task shows under its row

Under several rows in Settings there are small coloured chips. In general: red = work still to do, green = done, amber = needs attention or skipped, grey = information only. A chip with a heavier outline or a spinning icon is the one being worked on right now. Hover over a chip to see more detail.

Login update

A summary line, a Check now button and one chip per account that needs attention.

  • Summary examples: "3 of 5 still to update — working through them now", "All 5 logins were updated", or, when nothing is outstanding, "Every saved login is inside its expiry date — press Check now for the marketplace's own answer". While loading: "Reading the accounts…".
  • Marketplace · username · Expired — still to update. The tag says why: Expired (the saved login has run out), Expiring (it runs out shortly), Rejected (the marketplace refused it, whatever its expiry date says) or No login (never signed in on this computer). A person icon means automatic sign-in is off for that platform, so a person must sign in.
  • Highlighted, pulsing chip with "Signing in…" — the account being signed in right now.
  • Marketplace · username — updated. It stays on the list in green so you can see what was done.

How to check logins with the marketplace: click Check now. The app asks each marketplace whether each saved login really still works (expiry dates are only an estimate). The chips update with the answer. The button is greyed out while the Login update is running.

AJIO report sync

Two chips, Forward and Return:

  • Forward · 2 hours ago · data to date — last synced, and the latest date the backup covers.
  • Return · never synced — nothing has been synced on this computer yet.

Snapdeal report sync

  • Return · 1 day ago · data to date — when rows last arrived, and the date covered. Return · nothing collected yet if nothing has arrived.
  • 3 waiting at Snapdeal — reports requested that Snapdeal is still building. This is normal, not an error; the next run collects them.

Flipkart report sync

  • Orders · 1,240 rows · data to date · time ago and the same for Returns. nothing collected yet if none have arrived.
  • 2 waiting at Flipkart — reports still being built. Normal.

Refill Data

Between runs, one chip per marketplace:

  • Myntra 12 to refill — claims with blanks still to ask about.
  • Ajio nothing to refill or Ajio 8 filled — nothing waiting.
  • "· 5 past the limit" — claims already asked about 3 times without an answer; they are no longer asked. A small Reset button appears on that chip.
  • "asking now" with a spinning icon — this marketplace is being asked right now.

How to let "past the limit" claims be asked again:

  1. Click Reset on the marketplace's chip. It changes to Reset 5? showing how many claims.
  2. Click it again to confirm.
  3. A message says "Marketplace: 5 row(s) back in the refill — they are asked again on the next run."

While Refill Data runs, a progress line appears: "Running the Blanks pass", then "Finished the Blanks pass" (with "· it had nothing to ask" if there was nothing to do). Each marketplace shows waiting, a spinner while running, a tick when done, or skipped, with counts such as "40/120 checked · 6 changed · 3 skipped". A green "N up to date" badge means those claims were answered recently and were not asked again — that is work already done, not a problem.

Auto claim

A summary line and one row per marketplace showing Total, Success and Failed.

  • Summary examples: "2 of 3 marketplaces still to file — working through them now", "All 3 marketplaces are done", "4 claim(s) skipped — re-capture the login and they file on the next run". It may end with "· 7 not yet fileable".
  • If nothing is ready: "Nothing ready to file — 7 Pending claims still waiting on a missing account, POB ID or sub-order number." (Refill Data fills these.)
  • Red row — claims still to file, or some failed (extra text such as "2 left" or "1 no ticket id"). The Background Process page has the reasons.
  • Amber row with a key icon — "skipped — no login": the account has no working login, so nothing was attempted. Re-capture the login on the Login page; the claims file on the next run.
  • Green row — every claim this run had for that marketplace is filed.

Status change

Between runs, one chip per marketplace:

  • Ajio 14 due · 30 up to date — tickets due to be checked on the next run.
  • Myntra nothing due — all checked recently.
  • "Counting filed tickets…" while loading; "No filed ticket to check yet." if there are none.

While it runs, the same progress display as Refill Data appears, for the Claim status pass.

How to skip one marketplace during a run

If one marketplace is slow or keeps refusing during a run, you can skip just that marketplace and let the task carry on with the rest.

  1. While the task is running, find the marketplace being worked on. It has a small Skip button. This appears on the Login update board (Platforms tab), on the Auto claim row, and on the Refill Data / Status change progress chips.
  2. Click Skip. It changes to Skipping, and a message says "Marketplace will be passed over after the row in hand."

The item in hand is finished first, so nothing is left half-done. The marketplace is included again on the next run.

"Automations paused" — when logins need fixing

Every task after Login update needs working marketplace logins. If the Login update cannot fix every login, the app may pause all automations by itself, so it does not waste the night on logins the marketplace will refuse. A red box appears above the Automations switch:

  • Automations paused, followed by which logins need attention (or "Logins need re-capturing.").
  • A button: Re-capture on the Login page.
  1. Click Re-capture on the Login page.
  2. Sign in again for the accounts named (see Login).
  3. Automations start again by themselves once the logins are fixed — you do not need to touch the switch.
TipA login the marketplace refused because of a wrong password is not retried by the Login update and does not hold this pause. Verify it on the Login page.
NoteIf you switched Automations off, fixing logins does not switch them back on. Only you can.

Settings controlled by the TrackVid team

Some settings that change how automations behave are not in this app. They are set by the TrackVid admin team for your company, and the app follows them automatically. If you need one changed, contact the TrackVid team.

SettingWhat it controls
Desktop executionWhich marketplaces and automations (claims, master import) run on this computer. If a marketplace is not set to run here, it is handled by the TrackVid server instead and this app will not automate it.
API-based automationFor a marketplace that runs here, whether claims are filed through the marketplace's direct connection or by driving a browser.
Master import sync timeThe time each day the master import runs. This is separate from the schedule in Settings and has no time box in this app.
Auto-loginWhether the app may sign in to a marketplace by itself. When it is off, the Login update skips that platform's accounts ("Skipped — manual sign-in") and a person must sign in on the Login page.
